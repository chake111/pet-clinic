# 主流程测试计划与用例（2026-10-21）

## 1. 需求分析

以本次工作区源码、CONTEXT.md 与 docs/adr 为依据。包含已有未提交的问诊界面修改。测试基线的提交号、文件状态及构建结果另存。

| 需求 | 业务规则 | 依据 |
| --- | --- | --- |
| R1 | 主人选择自己的宠物及医生排班，创建预约扣一个号；重复预约被拒绝 | AppointmentService.create |
| R2 | 30 分钟内模拟支付；重复支付保持一致；取消待接诊预约退号，已支付则退款 | AppointmentService.pay/cancelLocked |
| R3 | 所属医生接诊已支付预约，填写病历、结束就诊；主人评价一次 | AppointmentService.accept/finish、MedicalRecordService、DoctorReviewService |
| R4 | 未支付超时取消；已支付且过就诊日仍待接诊标记未到诊 | AppointmentSweepTask、ADR 0002 |
| R5 | 免费问诊独立创建，双方交流、已读、结束后回看；建议到院作为消息保留 | ConsultService、ADR 0001 |
| R6 | 归属、角色、停用状态与会话处置约束在 REST/WebSocket 上生效 | CONTEXT.md、控制器与安全组件 |

## 2. 测试计划

顺序：需求分析 → 测试计划 → 用例设计 → 隔离环境搭建 → 执行 → 缺陷登记 → 回归 → 报告。

环境使用 MySQL 3307、独立 pet_clinic_test_<8位hex> 数据库、受限数据库账号、后端 8082。后端从当前代码构建。测试账号来自隔离库种子数据。浏览器如启用，使用独立前端端口并代理 8082。

执行层次：后端单元测试、前端单元测试与构建、真实 API 主流程、WebSocket 集成回归、浏览器交互验证。每项分别记录结果与证据。历史测试脚本在当前环境重新执行。

## 3. 测试用例设计

| 用例 | 操作 | 预期 |
| --- | --- | --- |
| M01 | 主人登录，创建宠物，查询医生及排班，预约 | 预约归属正确；余号减一；返回支付期限 |
| M02 | 同一宠物重复预约相同时段 | 拒绝；余号不再减少 |
| M03 | 未支付接诊；支付两次 | 首次接诊拒绝；两次支付状态一致 |
| M04 | 其他主人查询/支付/取消；其他医生和管理员接诊 | 权限拒绝；原单据保持不变 |
| M05 | 所属医生接诊、保存病历、结束，主人查看并评价 | 状态按 0→1→2 流转；病历可读；评价一次 |
| M06 | 已接诊取消、重复评价、完成后再次接诊 | 拒绝非法状态转换 |
| M07 | 未支付取消、已支付取消、重复取消 | 退号一次；支付状态分别未支付/已退款 |
| M08 | 两个请求争抢最后一个号；同宠物并发下单 | 成功数受容量约束；无重复有效预约 |
| M09 | 支付过期预约；触发超时清扫 | 支付拒绝；取消后退号一次 |
| M10 | 已支付预约改为昨日，尝试接诊/取消 | 标记未到诊；保留支付与已占容量 |
| C01 | 主人发起问诊，医生接入 | 不创建预约、不占号源；双方可见 |
| C02 | 双方发消息、已读、断线重连 | 消息持久化、未读一致、历史可回看 |
| C03 | 建议到院、结束会话、结束后发消息 | 建议保留；结束后写入拒绝，历史可读 |
| C04 | 非参与者访问；账号停用/令牌过期；管理员处置 | REST 与 WebSocket 权限规则一致 |
| C05 | 发送/关闭/屏蔽并发；病历首次保存并发 | 已有 audit_regression 断言成立 |
| U01 | 前端单元测试、生产构建 | 测试通过，构建成功 |
| U02 | 浏览器运行主要入口及支付交互 | 页面操作与展示符合用例，记录是否使用真实后端 |

## 4. 缺陷管理与回归约定

发现问题后记录编号、严重度、基线、前置条件、复现命令、预期/实际、代码位置及状态。状态使用：待复现、已确认、待修复、已修复待回归、已关闭。环境故障和测试脚本问题单独登记。修复后的问题必须重跑原用例与相关用例；当前需求以排查和报告为交付，业务修复建议随缺陷给出。

## 5. 完成依据

每个计划用例都有通过、失败或阻塞记录；失败项有证据；回归结果与首轮结果分开；报告注明实际覆盖范围、剩余问题和环境收尾情况。
