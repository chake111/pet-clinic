## 5. 缺陷管理

### T01：环境自检在已有 8082 服务时误报启动失败用例

- 类型：测试工具问题；严重度：低；状态：已确认，待修复。
- 复现条件：8082 已有可响应 `/api/v3/api-docs` 的测试后端。
- 命令：`python tools/qa_env.py selftest`。
- 预期：准确验证“立即退出”和“启动超时”的子进程，或明确提示要求空闲端口。
- 实际：输出 4 条 FAIL（两个“应当抛错”、两个“PID 未清理”）；身份核验用例跳过。
- 证据：`environment-selftest.txt`；停止后端后，同一命令通过，见 `environment-selftest-idle.txt`。
- 代码位置：`tools/qa_env.py:441` 的 `launch_and_wait`；第 457 行读取全局 API 就绪状态，第 733 行自检直接调用该函数，第 749 行才对后续身份用例检查端口占用。
- 原因：已运行服务满足 `api_ready()`，导致自检启动的无关 Python 子进程提前被判为就绪。
- 建议：自检的进程退出/超时用例注入独立就绪探针，或执行这些用例前验证专用端口空闲；增加“8082 已占用”的自检断言。
- 本次处置：停止测试后端后复跑自检；业务执行使用的 `instance` 校验始终通过。该工具修复作为后续任务保留。
