# 用户端设计约定

本文件保留当前实现仍适用的规则及理由。具体变量值以 `frontend/src/styles/main.css` 为准，组件局部样式以各 `.vue` 为准；理由是避免在文档复制一套无人同步的样式配置。

## 范围与布局

- 用户端页面、ClientLayout 与共享组件按本约定维护；后台保持自己的表格与表单布局。（依据：`layouts/ClientLayout.vue`、`layouts/AdminLayout.vue`）

- 全局变量与通用壳子放在 main.css，局部样式留在组件。（依据：`styles/main.css`、各组件 scoped 样式）

- Element 全局色阶随主色及语义色一起维护；用户端专用覆盖限定在 body.client-mode。（依据：`styles/main.css`、`router/index.js`）

- 常规页面保留首页、找医生、问诊、我的四个底部入口；问诊聊天页使用独立标题栏和返回入口，底部为消息输入区。（依据：`layouts/ClientLayout.vue`、`views/client/ConsultRoom.vue`）

- 用户端保持最大 760px 的居中单栏，内容留白统一 16px（`--page-margin`）：顶栏、正文、固定底栏和底部操作条共用 728px 的内容盒。359px 以下由 `max()` 的下限自然回到 16px，不再单独覆盖。（依据：`styles/main.css`、`layouts/ClientLayout.vue`）

- 医生列表在 640px 起用两列；首页科室默认展示既有排序前六项，窄屏三列、560px 起六列，支持展开全部。（依据：`views/client/DoctorList.vue`、`views/client/Home.vue`）

- 用户端外壳底栏 64px（`--tab-bar-height`）加安全区；底部操作条固定在底栏之上（`bottom: calc(64px + 安全区)`），定位、宽度上限（`--content-width`）、白底与投影由公共 `.pc-cta-bar` 提供，各页只负责高度与内部排布，自身高度按内容取 72 / 84 / 148 三档，正文按操作条实际高度预留。（依据：`styles/main.css`、`layouts/ClientLayout.vue`、`views/client/Booking.vue`）

- 横向号源列表保留滚动吸附；挂号页与医生详情共用 `.pc-date-strip` / `.pc-date-option`，页面只保留各自的伸缩基准与无号态。（依据：`styles/main.css`、`views/client/Booking.vue`、`views/client/DoctorDetail.vue`）

- 挂号先横向选日期，再显示当天时段；切日清除旧时段，固定提交栏展示已选时间并按实际高度避让正文。（依据：`views/client/Booking.vue`）

## 色彩与状态

- 品牌标识采用 Rausch #ff385c；两端承载白字的实心主操作统一采用 #d92549（`--color-action`）。用户端由 `body.client-mode` 绑定，后台由 `body.admin-mode` 在 `styles/admin.css` 统一绑定同一组令牌；`AppointmentDetail` / `Workbench` 的两处页面级 `:deep` 覆写已被全局规则遮蔽，保留为过渡，待下一轮删除。业务状态使用独立语义色。（依据：`styles/main.css`、`styles/admin.css`、`utils/dict.js`）

- 进行中用蓝、成功用绿、待办用橙、危险用红、终止用灰；状态胶囊带文字和前置圆点。（依据：`utils/dict.js`、`components/StatusChip.vue`）

- 金额、评分及表单选中态使用 ink；底部导航用深品牌红标记当前位置，浅粉指示块随路由滑动，焦点沿用 ink。（依据：`styles/main.css`、`ClientLayout.vue`、`components/DoctorCard.vue`）

- 破坏性操作使用危险文字或描边，并确认操作。（依据：`views/client/MyPets.vue`、`views/client/MyOrders.vue`）

- 自己的聊天气泡使用 ink，发送按钮使用品牌色。（依据：`components/ConsultPanel.vue`）

- 中性面用纯灰，普通卡片静息无阴影；浮起卡片与底部条分别复用 shadow-card、shadow-bar。（依据：`styles/main.css`、`components/DoctorCard.vue`）

## 文字与触控

- 字体栈保留中文系统字体回退。（依据：`styles/main.css` 的 `--el-font-family`）

- 医疗、聊天、公告长正文采用 16px / 1.7 行高；标签、状态和操作提示 14px；日期编号 13–14px；输入文字保持 16px。（依据：`styles/main.css`、用户端各页面）

- 普通按钮高 44px，大按钮高 48px，常规输入高 52px，小输入高 44px；文字按钮扩大点击区时避免与邻项重叠。（依据：`styles/main.css`）

- 卡片浮起等鼠标 hover 效果限定在 hover:hover 且 pointer:fine 的设备上。（依据：`components/DoctorCard.vue`、`views/client/Booking.vue`）

- 底部安全区在导航高度之外额外计算。（依据：`layouts/ClientLayout.vue`）

- 圆角复用 radius 系列变量，动效缓动复用 --ease。（依据：`styles/main.css`、`layouts/ClientLayout.vue`）

## 集中打磨后的补充约定（2026-10-04）

- 个人中心表单采用手机单列、宽屏两列；账号设置使用 44px 小输入，避免资料页过松。

- 长姓名、状态和详情值允许换行；窄屏预约标签等分可用宽度，不能截掉最后一项。

- 加载中、失败、空列表与对象不存在分别展示；失败提供重试，不用空态或持续加载遮罩代替。

- 表单错误文字参与正常布局，避免与下一项相撞。长弹窗高度扣除顶部间距，正文滚动、页脚操作固定在弹窗内。

- 宠物选项保留原生 radio 键盘行为；隐藏视觉控件时不使用 hidden 移除焦点。

- 已结束会话只显示结束说明，不继续出现可留言提示。

后续同类修改沿用这些规则，集中走查受影响页面。

## 真实流程收尾约定

- 列表筛选与页码写入地址，异步数据渲染后再恢复历史滚动位置。

- 提交函数阻止重复触发；失败提示由请求层统一显示，页面保留输入与重试入口。

- 聊天页不设置挤占低高度窗口的固定最小高度；末条消息不追加多余尾部留白。

- 预约详情有独立键盘入口，导航和评分控件提供具体的可访问名称。

## 输入与放大阅读补充

- 聊天回车发送必须先排除输入法组合事件，候选词确认不得清空草稿或发出消息。

- 带固定提交栏的症状输入区聚焦时滚动至可读区域，滚动留白覆盖顶栏、提交区及导航。

- 放大阅读与移动端检查应区分浏览器触屏模拟和真机验收。

## 统一可读性（2026-10-05）

- 用户端复用 `--font-reading`、`--font-label`、`--font-meta` 与 `--line-reading`，定义在 `body.client-mode`，后台保持既有文字密度。

- 主要对象姓名至少 16px；底部导航标签 14px，占高 64px 加安全区。指示块滑动 280ms，图标与文字过渡 200ms，支持减少动态效果。

- 宠物选项信息自然换行；预约卡症状完整展示；问诊列表仍可用单行摘要，通过会话入口阅读全文。

- 聊天时间使用明确的前景色，避免用透明度叠加背景；颜色检查以实际背景为准。

- 提示、校验、空态按 14px 阅读文字处理，不能靠缩小字号把内容塞进固定高度。状态胶囊和表单标签允许随内容长高。

- 本轮未删产品文字；早期实施记录中的字号是历史基线。

- 首页去掉重复欢迎语，科室提供展开与收起；游客从预约、问诊入口登录后回到原目标页。

- 问诊列表无论是否已有会话，都保留“发起问诊”入口。

- 挂号校验在对应区块显示错误，并定位到第一个未完成项；建单后关闭支付弹窗进入已有预约详情。

- 待支付预约突出付款状态，金额、支付和取消操作位于固定底栏；完整症状继续保留。

- 医生首页优先展示今日待接诊、接诊中及未读问诊，业务统计随后展示；管理员维持原概览。

- 接诊页摘要与病历按 1:2 分配桌面空间，病历顶部操作条随滚动保持可见。保存反馈区分未填写、已保存、未保存修改和处理中。

- 有修改时结束就诊须明确选择保存或放弃；保存失败保留输入，离开页面提示未保存内容。没有病历仍可结束，之后可以补写。

## 医生端问诊布局（2026-10-20）

- 医生端会话标题并排展示宠物、主人和灰字状态。两端共用白色阅读画布与品牌粉色气泡，本人发送使用primary-soft，对方消息底色更浅；宽度随内容收缩并限制在阅读列82%内，手机为92%。姓名、时间和送达状态放在气泡上方。
- 两端共用一体式回复框，两行起步、最多四行，聚焦时外缘显示淡粉边框与外圈。底部放图片与圆形发送按钮，医生端另有建议到院；用户端收到到院建议后保留预约入口。手机端保留安全区边距。
- 病情资料由标题栏打开右侧400px抽屉，700px及以下使用底部抽屉。小结在资料首位，保留症状、照片及脱敏联系方式。
- 手机问诊详情收起后台侧栏，通过返回入口恢复列表导航。聊天区按可用视口分配高度，消息独立滚动，使用细灰色透明轨道滚动条。

## 多维评分展示（2026-10-18）

- 评价的三个维度（综合评分、服务态度、诊疗效果）必须同时展示且各自带文字标签，不能只给综合评分加星级、把另外两项压成无标签附注。（依据：`views/admin/Reviews.vue`、`views/client/ReviewForm.vue`）

- 多维度并排时统一为「标签 + 数值 + ink 量条」，三个维度共用基线、列宽与量条长度；量条只辅助比较，数值必须可直接读，且不依赖颜色。（依据：`views/admin/Reviews.vue`）

- 状态只由 StatusChip 承担。列表中的默认状态（如评价的“显示中”）不常驻彩色胶囊，只标记例外状态（“已隐藏”），避免状态色抢走评分和正文的注意力。（依据：`views/admin/Reviews.vue`、`components/StatusChip.vue`）

- 操作按钮不复用状态语义色：隐藏/恢复显示使用中性描边，破坏性或不可逆动作才用危险色。（依据：`views/admin/Reviews.vue`）

## 关联单据的识别（2026-10-18）

- 列表里引用另一张单据时，不显示裸主键。至少给出业务编号、发生日期和对象名，例如评价行显示「宠物 + 就诊日期 + 预约单号」，主键只留在接口和链接地址里。（依据：`views/admin/Reviews.vue`、`vo/ReviewVo.java`）

- 能点进关联单据的编号使用可访问的链接（含 `title` 说明完整编号），并在目标页提供回到来源列表的返回入口；后端把关联上下文字段随列表一次性返回，避免前端逐行补查。（依据：`views/admin/Reviews.vue`、`views/admin/AppointmentDetail.vue`、`service/DoctorReviewService.java`）

## 医生预约清单（2026-10-18）

- 医生账号进入预约管理默认落在今天，日期条件写入地址，刷新与分享后保持一致；重置恢复“今天”而不是全部日期。管理员保留全部日期与跨医生表格检索。（依据：`views/admin/Appointments.vue`）

- 医生视图按就诊日期分组、组内按开始时间排序，日期、时段和状态在窄屏与放大阅读时正常换行，不靠横向滚动隐藏。（依据：`views/admin/Appointments.vue`）

- 行内主操作随状态给出可执行的下一步：待接诊且已支付为“接诊”，就诊中为“继续接诊 / 完成”，已完成按有无病历给“写病历”或“查看病历”。同一行只保留一个实心主按钮，详情与取消保持文字链。（依据：`views/admin/Appointments.vue`）

- 医生列表已限定为本人，不再重复医生姓名与科室；默认支付状态（已支付）不常驻胶囊，只在未支付、已退款时显示。（依据：`views/admin/Appointments.vue`、`components/StatusChip.vue`）

- 一次性状态迁移在请求期间锁住该行按钮，避免接诊或结束被连点两次。（依据：`views/admin/Appointments.vue`）

- 行内排布由卡片容器宽度决定（容器查询），因为后台侧栏伸缩会改变实际可用宽度；症状正文完整换行，不截断。（依据：`views/admin/Appointments.vue`）

- 医生清单的次要信息带「主人」「单号」文字标签；单号同时给出完整编号的 `title`。空态给出下一步（今天无单时查看未来 7 天），首次加载完成前不渲染空态。（依据：`views/admin/Appointments.vue`）

## 科室图标（2026-10-18）

- 科室图标不使用 emoji：emoji 的字形、颜色和基线由系统字体决定，同一份数据在 Windows、macOS、Android 上长得不一样。也停在过一版单色线性图标，因用户要求「像给漫画上色」而改为**实心色块 + 同色深一档描边 + 小面积象牙白高光**的三层结构，由 `components/DeptIcon.vue` 渲染。（依据：`components/DeptIcon.vue`、`utils/deptIcons.js`、`views/client/Home.vue`、`docs/adr/0009-illustrated-department-icons.md`）

- 每个科室一个固定色相，颜色存在前端 `utils/deptIcons.js`，不进数据库。色值需同时满足三条：白底对比度 ≥3:1（WCAG 1.4.11）、十色两两 CIE76 色差尽量大、与动作色和六种语义色拉开距离。当前十色两两最小色差 22.9，与语义色最近距离 17.0，白底对比度最低 3.65。（依据：`utils/deptIcons.js`）

- 插画色是独立的颜色角色，见 `CONTEXT.md` 的「插画色」：只用于图标内部，不复用品牌红 `#ff385c` 与状态语义色（进行中蓝、成功绿、待办橙、危险红、终止灰）。急诊用急救箱而不是红心，因为心形在 32px 下会被读成「收藏」。（依据：`CONTEXT.md`、`utils/deptIcons.js`）

- 同组图标按**墨迹的几何均值** `sqrt((w+pad)*(h+pad))` 归一，不按 viewBox、也不按外接框长边：斜放 45° 的图标（疫苗）长边由对角线决定，按长边归一会让它观感小一圈。线宽按 `V/32` 反向补偿，十个图标渲染后主体描边一致。（依据：`components/DeptIcon.vue`）

- 科室宫格里卡片本身就是容器，图标直接落在卡面，不再套一层浅灰底块；底块加描边卡片会读成「一格套一格」。图标 32px、科室名用 body 色，hover 只加深卡片描边。（依据：`views/client/Home.vue`）

- `department.icon` 存图标键名（`stethoscope`、`surgery`、`skin`、`eye`、`tooth`、`imaging`、`vaccine`、`nutrition`、`emergency`、`exotic`），键名与图标的对应关系只在前端 `utils/deptIcons.js` 维护；后台选择器直接复用这份清单，并显示中文名称，不只给一个无法形容的图形。（依据：`utils/deptIcons.js`、`views/admin/Departments.vue`）

- 历史 emoji 与图片 URL 继续兼容：emoji 按映射表落到对应图标，图片 URL 仍按 `<img>` 渲染，避免迁移前掉落图标。（依据：`components/DeptIcon.vue`、`utils/deptIcons.js`）

- 彩色图标只出现在首页科室宫格与后台科室管理的列表/选择器；医生卡片、预约详情等处的科室仍是纯文字，避免颜色在列表里变成噪音。（依据：`views/admin/Departments.vue`、`views/client/Home.vue`）

- 高对比模式下彩色图标降级为单色描边（`CanvasText`），不做暗色主题。（依据：`components/DeptIcon.vue`）
